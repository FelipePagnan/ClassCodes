Camada Core

° Também chamada de Domain, é a camada central da aplicação, onde não deveria ter dependências entre outros projetos
° Seus principais componentes são (relcionado com DDD):
    ° Entities
    ° ValueObjects
    ° Repositories (interfaces)
    ° Enums
    ° Serviços de dominio
    ° Eventos dominio

Camada Infrastructure

° É aqui onde são implementadas as integrações com componentes da infra-estrutura ou outros sistemas, como banco de dados, APIs externas, sistemas legados, serviços de Cloud, etc
° Seus principais componentes são:
    ° Implementações de Repositorios
    ° Serviços de Integração com outros sistemas
    ° Serviços de integração Cloud
    ° Serviços de integração com Message brokers
    ° DTOs relacionados aos serviços acima

Camada Application

° É aqui onde são implementados os casos uso da aplicação, envolvendo os modelos de dados que a aplicação recebe do usuário/mundo exterior
° Seus principais componentes são:
    ° Serviços de aplicação (geralemnte 1.1 para funcionalidades)
    ° Commands e Queries (se utilizar o padrão CQRS)
    ° Modelos de entrada e saida (DTOs)
    ° Subscribers/ Consumers de eventos

Camada Web/API

° É aqui onde outros sistemas se integram com a aplicação/API. Esses sistemas podem ser front-end, desktop ou mesmo outras APIs
° Seus principais componentes são:
    ° Controllers
    ° Startup (que orquestra a configuralçai da aplicação)

O que é CQRS

° Sigla para Command Query Responsibility Segregation, é um padrão que separa a responsabilidade de escrita e leitura
° É um padrão bastante utilizada não somente por promover uso de modelos/bancos de dados diferentes mas por melhorar a legibilidade, testabilidade e manutenção
° Seus principais componentes são: Commands e Queries, e seus respectivos Handlers
